# Git basics #1: your first commit

Series: Git Basics (1 of 1 so far) · Target length ~76s · Pace ~150 wpm
Terminal beats match `body.tape` markers. Pause where the screen is busy; trim silence in edit.

> On screen: `git init`, `ls -a`, `git status -s`, `git add`, `git commit`, `git log --oneline`.

## [0:00-0:05] Hook
Git saves snapshots of your project. Let us make one right now.

## [0:05-0:17] Init
Make a folder, then run git init. That turns it into a repository. Look closely with ls dash a and you will see a hidden dot git folder. That is where all your history lives.

## [0:17-0:31] Status
Now create a file, and ask git what it sees with git status. The double question mark means untracked. Git notices the file, but it is not watching it yet.

## [0:31-0:44] Add
Git add stages the file. Staging is you choosing what goes into the next snapshot. Run status again and the file is ready to commit.

## [0:44-0:58] Commit
Git commit takes the snapshot. The dash m flag is your message, so say what changed, in plain words. Future you will thank present you.

## [0:58-1:09] Log
Git log shows your history. Dash dash oneline keeps it to one line per commit. One snapshot, saved, and you can always come back to it.
